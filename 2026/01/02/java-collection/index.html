从使用场景出发理解常用集合

在业务代码中，集合的选择通常不是“哪个都能用”。理解数据是否有序、是否允许重复、如何查找，以及并发场景，能让代码更清晰，也能避免后期修改数据结构。

常用接口

  • List：关注元素顺序，允许重复。需要按下标访问或保留插入顺序时使用。
  • Set：关注元素唯一性。需要去重时使用，是否有序取决于具体实现。
  • Map：保存键值映射。需要通过唯一键快速定位数据时使用。

常见实现

ArrayList 基于动态数组，随机访问快，尾部追加通常效率较高；在中间插入或删除会移动后续元素。LinkedList 适合频繁在已知节点位置进行操作，但它的随机访问成本较高，不能因为“链表插入快”就默认选择它。

HashSet 和 HashMap 依赖哈希表，平均情况下查找效率较高。使用自定义对象作为键或集合元素时，必须正确实现 equals 和 hashCode，否则可能出现逻辑重复或无法查找的问题。

如果需要保持插入顺序，可以考虑 LinkedHashMap；如果需要按键排序，可以考虑 TreeMap。选型应服从业务要求，而不是只看类名。

实际开发中的检查点

  1. 是否真的需要保持顺序？
  2. 是否允许重复元素？
  3. 查找操作是否远多于插入操作？
  4. 是否存在多线程同时读写？
  5. 集合规模是否可能很大，需要关注初始容量和内存占用？

集合只是工具，先描述清楚数据和操作，再选择实现，通常比死记复杂度更可靠。
